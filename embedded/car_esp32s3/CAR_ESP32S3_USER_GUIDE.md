# ESP32-S3 循迹小车使用说明

本说明适用于 `embedded/car_esp32s3` 中的车辆固件。当前入口驱动感为八路 I2C 灰度传感器和两路直流电机，并通过 Wi-Fi/UDP 向 ROS 与地面站发送车辆状态。

> 当前 `car_esp32s3.ino` 使用自主循迹与 Wi-Fi/UDP 集成入口；上电后自动循迹，并向 ROS 和地面站发送当前循迹状态。该入口暂不计算编码器速度、位移和 B/D/A/COMPLETE 路线事件。

## 1. 功能范围

车辆固件负责：

- 使用感为八路灰度传感器识别赛道中心。
- 以 200 Hz PID 控制左右轮差速循迹。
- 自动开始循迹时产生 `START` 事件；当前入口的位移和速度遥测保持为 0。
- 每 50 ms 向 ROS 和 HMI 发送遥测，每 1 秒发送心跳。
- 在持续失线或硬件初始化失败时保持电机制动。

车辆上电自检通过 1.5 秒后自动从 `READY` 进入 `RUNNING`。ROS 和地面站不能远程启动或直接控制电机。

## 2. 硬件与接线

### 2.1 示例引脚

以下引脚对应 `config_local.example.h`。烧录前必须与实际开发板和接线核对。

| 功能 | ESP32-S3 GPIO |
| --- | --- |
| 灰度传感器 SDA | GPIO1 |
| 灰度传感器 SCL | GPIO2 |
| 左电机 PWM / IN1 / IN2 | GPIO6 / GPIO7 / GPIO8 |
| 右电机 PWM / IN1 / IN2 | GPIO9 / GPIO10 / GPIO11 |
| 左编码器 A / B | GPIO12 / GPIO13 |
| 右编码器 A / B | GPIO14 / GPIO15 |
| 启动按钮 | GPIO16，低电平有效 |

### 2.2 灰度传感器接线

感为八路灰度传感器要求 4.5～5.5 V 供电，ESP32-S3 GPIO 只能使用 3.3 V 电平。SDA 和 SCL 应经过双向 I2C 电平转换器：

```text
ESP32-S3 3V3   -> 电平转换器 LV
ESP32-S3 GPIO1 -> 电平转换器 LV-SDA
ESP32-S3 GPIO2 -> 电平转换器 LV-SCL

稳定 5V        -> 电平转换器 HV
稳定 5V        -> 灰度传感器 5V
传感器 SDA     -> 电平转换器 HV-SDA
传感器 SCL     -> 电平转换器 HV-SCL
所有 GND       -> 共地
```

注意事项：

- 不要将被上拉到 5 V 的 SDA/SCL 直接连接 ESP32-S3。
- 传感器板的 SDA/SCL 上拉跳帽连接的是 5 V。电平转换器高压侧已有上拉时不要重复安装。
- 传感器使用稳定、经过滤波的 5 V，不要直接与电机共用不稳定的电源输出。
- I2C 线尽量短，并与电机线分开布线。
- 建议传感器检测面距赛道约 20 mm，安装完成后再校准。

### 2.3 I2C 地址

程序以 100 kHz 初始化 I2C，并自动扫描 `0x4C`～`0x4F`。这四个地址对应传感器出厂软件地址和 AD1/AD0 跳帽的四种组合，因此一般不需要手工填写单个地址。

启动时程序会执行：

1. 扫描地址并发送 Ping 命令 `0xAA`。
2. 校验传感器返回值是否为 `0x66`。
3. 使用 `0xC1` 读取固件版本。
4. 固件为 V3.6 以上时使用 `0xCF` 开启八通道归一化。
5. 使用 `0xCE` 启用全部通道，再通过 `0xB0` 读取八路模拟量。

手册正视图中的探头从左到右编号为 8～1，而 I2C 数据按通道 1～8 返回。默认配置会自动反转顺序，使 PID 数组保持从车体左侧到右侧排列。

## 3. 传感器安装与校准

传感器固定位置或离地高度变化后，应重新执行黑白场校准：

1. 避开强烈阳光，保持最终安装高度和角度。
2. 长按传感器校准按钮约 4 秒。
3. 指示灯快速闪烁后松开按钮，等待指示灯慢闪。
4. 将全部探头置于黑场，短按一次按钮，等待记录完成并恢复慢闪。
5. 将全部探头置于白场，短按一次按钮，等待记录完成且指示灯熄灭。
6. 分别用黑线和白底检查八个通道的数据指示灯。

传感器带有校准记忆，正常断电重启后不需要重复校准。安装高度、赛道材质或环境光明显变化时仍应重新校准。

## 4. Arduino 环境

| 项目 | 设置 |
| --- | --- |
| Arduino IDE | 2.x |
| ESP32 core | 项目基线 `3.0.7-cn`，要求 `3.0.6` 以上 |
| Board | `ESP32S3 Dev Module`，最终以实物板型为准 |
| 串口波特率 | `115200` |

车辆程序只使用 ESP32 core 自带的 Arduino、Wi-Fi、UDP 和 Wire 库，不需要安装第三方传感器库。

## 5. 本地配置

首次烧录前，将示例配置复制为本地配置：

```powershell
Copy-Item .\embedded\car_esp32s3\config_local.example.h `
  .\embedded\car_esp32s3\config_local.h
```

编辑 `config_local.h`，至少检查以下内容。

### 5.1 网络配置

- `WIFI_SSID`：封闭热点名称。
- `WIFI_PASSWORD`：WPA2 密码。
- `AUTH_KEY`：与 ROS、地面站一致的 32 字节随机 HMAC 密钥。
- `ROS_IP`、`HMI_IP`：ROS 和地面站的实际地址。
- `LOCAL_UDP_PORT`、`ROS_UDP_PORT`、`HMI_UDP_PORT`：三端 UDP 端口。

示例端口为：

| 节点 | UDP 端口 |
| --- | ---: |
| ROS | `42000` |
| 小车 | `42001` |
| 地面站 | `42002` |

真实密码和密钥只能写入已被版本控制忽略的 `config_local.h`，不要写回示例文件。

### 5.2 车辆参数

- `LINE_SENSOR_SDA_PIN`、`LINE_SENSOR_SCL_PIN`：I2C 引脚。
- `LINE_SENSOR_CHANNELS_REVERSED`：传感器安装方向相反时改为 `false`。
- `LINE_IS_DARK`：黑线设为 `true`，白线设为 `false`。
- 电机和编码器 GPIO：必须与驱动板接线一致。
- `MOTOR_BRAKE_HIGH`：必须符合电机驱动器的制动逻辑。
- `LEFT_ENCODER_INVERTED`、`RIGHT_ENCODER_INVERTED`：用于校正编码器正方向。
- `WHEEL_DIAMETER_M`、`ENCODER_COUNTS_PER_REVOLUTION`：用于里程换算。
- `BASE_MOTOR_COMMAND` 和 PID 参数：必须在架空和低速条件下逐步标定。
- `ROUTE_B_M`、`ROUTE_D_M`、`ROUTE_A_M`、`ROUTE_COMPLETE_M`：必须按实际赛道重新测量。

## 6. 编译与烧录

### 6.1 Arduino IDE

1. 打开 `embedded/car_esp32s3/car_esp32s3.ino`。
2. 选择实际 ESP32-S3 开发板；通用板可先选 `ESP32S3 Dev Module`。
3. 使用支持数据传输的 USB 线连接开发板。
4. 选择正确串口。
5. 点击“验证”，确认编译成功。
6. 点击“上传”，等待烧录完成。
7. 打开串口监视器，将波特率设为 `115200`。
8. 按一次开发板复位键，观察启动自检。

### 6.2 Arduino CLI

在项目根目录执行：

```powershell
arduino-cli compile --fqbn esp32:esp32:esp32s3 `
  --library .\embedded\shared_protocol `
  .\embedded\car_esp32s3
```

编译和烧录前必须确认正在使用真实的 `config_local.h`。示例配置中的热点名称和密码不能用于实车。

## 7. 自主黑线循迹模式

当前 `car_esp32s3.ino` 直接运行自主循迹控制，不再创建 UART 测试任务，也不等待 Wi-Fi、编码器或启动按钮。传感器识别到黑线后使用 PID 计算左右轮差速；弯道会自动降速，急弯时允许内侧轮反转。短暂丢线时车辆按最后看到黑线的方向找线，350 ms 内仍未找回则制动。

串口每 200 ms 输出一次循迹状态：

```text
[循迹] error=+0.321 strength=0.247 left=+0.56 right=+0.16
```

`error` 为负表示黑线偏左，为正表示黑线偏右；`left` 和 `right` 是左右电机命令，范围为 `-1`～`1`。当前模式在识别不到黑线时不会持续盲目行驶。

## 8. 启动与运行

### 8.1 首次上电

首次测试必须架空车轮，并先关闭或断开电机动力电源：

1. 检查 5 V、3.3 V、电平转换器和共地接线。
2. 检查 TB6612FNG 的 `VM`、`VCC`、共地、使能状态以及六根电机控制线。
3. 接通 ESP32 与传感器电源。
4. 查看串口自检结果。
5. 确认传感器正常后，再接通电机动力电源。

正常的传感器启动日志类似：

```text
[自检] ESP32-S3 黑线循迹启动
[循迹] 感为八路 I2C 已就绪，地址=0x4F，固件=V3.14，归一化=开启
[循迹] 黑线跟随已就绪，1.5 秒后开始
```

实际地址由 AD1/AD0 跳帽决定，显示 `0x4C`～`0x4F` 都可能是正常结果。

### 8.2 开始运行

1. 架空车轮，将传感器中间两路对准黑线后上电。
2. 确认黑线偏向传感器右侧时左轮加速、右轮减速；方向相反则切换 `LINE_SENSOR_CHANNELS_REVERSED`。
3. 确认左右轮都以正方向行驶，再将小车放到低速测试赛道。
4. 复位后有 1.5 秒准备时间，随后识别到黑线即自动行驶。
5. 根据实车振荡和过弯情况逐步调整 `BASE_MOTOR_COMMAND`、`PID_KP`、`PID_KI` 和 `PID_KD`。

### 8.3 路线事件

默认距离配置如下，必须按实际赛道标定：

| 累计距离 | 事件 | 行为 |
| ---: | --- | --- |
| 0 m | `START` | 按钮启动后上报 |
| 1.50 m | `B` | 上报 B 点事件 |
| 4.00 m | `D` | 上报 D 点事件 |
| 6.50 m | `A` | 上报 A 点事件 |
| 8.00 m | `COMPLETE` | 制动并进入完成状态 |

每个事件使用同一个 `event_id` 重复发送 5 个成功帧，接收端应按事件 ID 去重。

## 9. 网络与遥测

车辆通过 UDP 同时向 ROS 和 HMI 发送：

| 数据 | 周期 | 内容 |
| --- | ---: | --- |
| 车辆遥测 | 50 ms | 状态、弯道、事件、位移、速度、循迹误差、质量和故障标志 |
| 心跳 | 1 s | 发送者、启动 ID、序列号和单调时间 |

数据包使用 CRC16 检错和 HMAC-SHA256 身份认证，并通过启动 ID 和递增序列号拒绝重复包及旧包。

当前车辆的“网络健康”只表示 ESP32 仍连接 Wi-Fi 且 UDP 已启动，不代表 ROS 进程一定在线。ROS 停止但热点仍保持连接时，车辆不会因为 ROS 无响应自动停车。

## 10. 状态与故障

### 10.1 车辆状态

| 状态 | 含义 |
| --- | --- |
| `READY` | 初始化完成，等待实体按钮 |
| `RUNNING` | 正在循迹运行 |
| `COMPLETE` | 到达完成距离并制动 |
| `SAFE_STOP` | 故障锁存并制动 |

进入 `SAFE_STOP` 后不会自动恢复。排除故障后必须断电检查或按复位键重新启动。

### 10.2 故障码

多个故障可以按位组合。

| 数值 | 含义 | 触发条件 |
| ---: | --- | --- |
| `0x0001` | Wi-Fi 超时 | 运行中 Wi-Fi/UDP 断开超过 1 秒 |
| `0x0002` | 丢线或传感器不可用 | 无有效线路达到 250 ms，或传感器初始化失败 |
| `0x0004` | 编码器异常 | 无运动、左右轮长期不一致或速度跳变异常 |
| `0x0008` | PID 周期超时 | 单次控制超过 4 ms 或调度严重落后 |
| `0x0010` | 启动按钮卡住 | 按钮持续按下超过 3 秒 |
| `0x0020` | 电机故障 | PWM 初始化失败 |
| `0x0040` | 数据陈旧 | 协议保留，由接收端状态机使用 |
| `0x0080` | 协议错误 | 协议保留，由接收端或其他节点使用 |
| `0x0100` | 没有已确认任务 | 协议保留，由任务状态机使用 |
| `0x0200` | 欠压复位 | ESP32 检测到 Brownout 复位 |

## 11. 首次台架测试

按以下顺序测试，不要直接把未验证的小车放到赛道上：

1. 断开电机动力电源，只给 ESP32 和传感器供电。
2. 确认串口识别到传感器地址、固件版本和归一化状态。
3. 用黑线依次遮挡八个探头，确认物理左右方向与程序一致。
4. 架空车轮，以低占空比确认左右电机方向和制动逻辑。
5. 正转左右车轮，确认两个编码器累计方向都为正。
6. 短按启动按钮，确认只产生一次 `START`。
7. 断开 SDA 或 SCL，确认车辆立即制动并在 250 ms 后锁存故障。
8. 运行中关闭热点，确认约 1 秒后锁存停车。
9. 在低速短赛道上调整传感器方向、黑白线极性和 PID。
10. 最后标定轮径、编码器每圈计数以及 B/D/A/完成距离。

## 12. 常见问题

### 12.1 串口提示未检测到传感器

- 检查传感器是否获得稳定 5 V。
- 检查 ESP32、传感器和电平转换器是否共地。
- 检查 SDA/SCL 是否接反。
- 检查电平转换器 LV/HV 方向和两侧上拉。
- 确认地址仍位于 `0x4C`～`0x4F`；软件修改过地址的模块需要恢复出厂地址或调整扫描范围。
- 缩短 I2C 线并远离电机线。

### 12.2 小车朝远离黑线的方向转

- 确认传感器正视安装时物理编号是否为左侧 8、右侧 1。
- 切换 `LINE_SENSOR_CHANNELS_REVERSED`。
- 检查左右电机是否接反。
- 确认赛道为黑线时 `LINE_IS_DARK=true`。

### 12.3 一按启动就报告 Wi-Fi 超时

- 确认已经创建并填写 `config_local.h`，没有继续使用示例热点名称。
- 检查热点、密码、固定 IP 和 UDP 端口。
- 确认热点未启用客户端隔离。
- 启动前等待串口出现“UDP 已监听端口”。

### 12.4 一启动就报告编码器异常

- 检查左右编码器 A/B 接线和供电。
- 检查 `LEFT_ENCODER_INVERTED`、`RIGHT_ENCODER_INVERTED`。
- 核对每圈计数和轮径。
- 架空检查车轮转动时是否持续产生计数。

### 12.5 PID 周期超时

- 检查 I2C 是否存在接触不良或错误上拉。
- 保持 I2C 频率为 100 kHz，线缆尽量短。
- 不要在控制循环中增加阻塞式串口输出或延时。
- 降低 PID 参数前先排除传感器通信问题。

## 13. 使用限制

- 路线节点由编码器累计距离判断，不识别真实路标或路口。
- 起跑前推动小车可能改变编码器累计距离，应在起点静止上电。
- 传感器固件低于 V3.6 时不会开启硬件归一化，串口会显示“归一化=关闭”，此时需要实车复核 `MIN_LINE_STRENGTH`。
- 当前固件没有远程启动、遥控驾驶或自动故障恢复功能。
- 示例 PID、轮径、编码器计数和路线距离都必须经过实车标定。
